## What worked
- Checkpointed generation (C0 to C6) with a self-repair budget: one repair in the Android run, none in web.
- A harness that stays platform-neutral: web and Android used the same `/generate` command and pipeline, only conventions and templates differ.
- Verified wrapper and lockfile templates kept the generated builds reproducible.

## What went wrong
- **Budget:** a single Android generation used a full Claude Pro 5-hour window. Cloud agents, claude.ai and runs share one pool, so the later phases could not run.
- Header check treated machine-local `local.properties` as an unlisted file; fixed in the harness (142 tests).
- Allowlist denials (compound commands, `for` loops) cost turns; the run recovered each time.
- Git trailer and attribution rules took more effort than planned (decisions 0003 and 0015).

## What to improve
- Measure cost per checkpoint early and size the plan to the budget before starting.
- Make generated tests carry AC ids so `check_trace` can run unchanged.
- Allow `for` loops and `; echo` variants in the generate allowlist.
