# Review P2 / server — round 1

Scope: `server/` (645 lines, so Opus is used above the 400-line threshold) and `tests/protocol/` at `main` 8b9afc0, reviewed against `spec/core/protocol.md`,
`spec/core/server-behavior.md` and `spec/core/schema/` as they stand. The launch named no `diff.meta.json`, so I did not run
`check_snapshot.py`. I reviewed the whole tree at the SHA above. I did not review the 13 open questions in
`docs/runs/P2/spec-issues.md` (S-1..S-13) as defects. They come up below only where the server also departs from the
current spec text.

Severity scale: **blocker** breaks spec behavior or correctness and must be fixed before P2 exits. **major** must be
fixed in this round but does not on its own break the contract (in practice, a test gap that hides a blocker).
**minor** should be fixed and can follow. **nit** is cosmetic. Front-matter counts equal the tagged lines below.

How I checked: `python3 tests/protocol/run.py` passes (121 tests, OK, 5.5 s, Python 3.13). I also ran throwaway probes
against a real `server/start.sh --port 0` process (not committed, kept under `.work/rev-p2-probes/`): raw sockets for
keep-alive, a nesting-depth sweep, a concurrent stress run (up to 64 threads, 1200 mixed sends, duplicates and polls),
and HTTP framing edge cases.

## Findings

- [blocker] server/aware_server/state.py:82-83 (with api.py:107-110 and jsonvalue.py:37-53) — **a valid E3 can return `500` and consume a `seq` value.** `accept()` increments `self._seq` and then builds `Delivered`, whose `__init__` serializes the payload with the recursive `jsonvalue.dumps`. The pre-check at api.py:108 runs the same `dumps` two stack frames higher, so one nesting depth passes the pre-check and then raises `RecursionError` inside the lock, after the counter has already moved. Evidence (probe, type `x`, payload `{"a": [[...]]}`): depths 300–491 → `201`, depth **492 → `500 internal_error`**, 493 and above → `400 malformed_request`. After 192 accepted sends the next new envelope got seq **194** instead of 193. This breaks CORE-SEQ-001 ("rejected requests MUST NOT consume a value") and CORE-SRV-004 (state changed without the envelope being stored), and it answers a request that is valid under CORE-EXT-001 / CORE-SRV-040 with `500`. A conforming client treats `500` as class R and resends the same entry every cycle (CORE-OUTBOX-004), so its outbox stalls forever and every retry burns another seq. Fix in: server/aware_server/state.py + api.py. Serialize the payload once in `api.send` (before taking the lock) and pass the text into `Delivered`. Increment `_seq` only after everything that can raise. Make `dumps` iterative, or derive the pre-check and the store from one call, so the two can never disagree. Add a regression test at the boundary depth (see the second major).
- [blocker] server/aware_server/httpd.py:62-83 (body handling in `_read_body`, 85-100) — **an unread request body corrupts a kept-alive HTTP/1.1 connection.** The body is read only for E2/E3 after routing. For 404, 405, E1/E4/E5 GETs that carry a body, and OPTIONS with a body, the connection stays open (`close_connection` is not set) and the unread bytes are parsed as the next request line. Evidence (probe, one socket, request 1 followed by `GET /v1/users`): `POST /v1/info` with a body → `405`, then the valid GET gets **`405 method_not_allowed` "Unsupported method ('{"name":"alice","capabilities":[]}GET')"**. The same happens after `GET /v1/info` with a body (`200` then the bogus `405`), `POST /v1/nowhere` (`404` then `405`), `PUT /v1/session`, and `OPTIONS /v1/session` with a body. A valid request gets a wrong status and code, which breaks CORE-HTTP-001 (HTTP/1.1) and CORE-ERR-001. Correct clients rarely send these requests, but test suites and pooled clients (QA in P5, OkHttp, fetch) reuse connections. Fix in: server/aware_server/httpd.py. In `_serve`, when the request declares a body (`Content-Length` > 0 or any `Transfer-Encoding`) that was not consumed, set `self.close_connection = True` (the existing `_drain` already handles it), or read and discard up to `BODY_MAX_BYTES`.
- [major] tests/protocol/test_transport.py:112 and tests/protocol/harness.py:138 — `test_CORE_SRV_030_body_is_not_required_to_be_read_for_get_requests` asserts only the first response on a fresh connection, so it passes while the connection is left corrupted (second blocker). `Client.call` opens a new connection per request, so no test in the suite can observe connection-reuse defects. `test_CORE_HTTP_001_..._keep_alive_http_1_1` (test_transport.py:83) covers only well-formed requests. Fix in: tests/protocol/test_transport.py. On one `HTTPConnection`, send each of {405 with body, 404 with body, GET with body, 415, 413, 400 after body read}, then a valid request, and assert the valid request gets its correct `200`.
- [major] tests/protocol/test_transport.py:73 — the only nesting case is 60000 levels, which fails at JSON parse time. Nothing exercises the depth window where parse succeeds and storing fails, and no test asserts that a failed or rejected deep payload leaves the counter unchanged. This gap is why the first blocker shipped green. Fix in: tests/protocol/test_send.py or test_relay.py. Sweep depths around the interpreter limit (or compute the boundary) for a non-core type, assert that no response is `5xx`, and assert that the next new envelope gets the next contiguous seq.
- [minor] server/aware_server/api.py:107-110 — the nesting rejection is a rule the spec does not contain (S-10 is open). It is also raised after step 4, so its order contradicts CORE-ERR-002, which puts `malformed_request` before `epoch_mismatch` and the `invalid_*` codes. Evidence: a payload nested 700 deep (parses fine, fails `dumps`) with a wrong epoch → `409 epoch_mismatch`; with a bad `from` it would be `invalid_name`. Fix in: server/aware_server/api.py. Once the first blocker is fixed, enforce one depth bound inside step (2), at parse time, so the rejection keeps the precedence of every other `malformed_request`. Or drop the bound if TL rules on S-10 that the body limit alone governs.
- [minor] server/aware_server/httpd.py:171-174 — `ThreadingHTTPServer` keeps the default listen backlog `request_queue_size = 5`. Bursts of concurrent connects get reset before a handler runs. Evidence: 64 client threads → 29 of 900 POSTs got `ConnectionResetError`, 16 threads → 1. The server logged 1199 lines for 1201 requests, so those connections never reached the handler. This weakens CORE-SRV-003 ("a slow or stalled connection MUST NOT delay any other request") under parallel test load. Logic invariants held under the same stress: seqs contiguous, polls ascending, each duplicate accepted once. Fix in: server/aware_server/httpd.py, `request_queue_size = 128` (or `socket.SOMAXCONN`) on `AwareServer`.
- [minor] server/aware_server/httpd.py:150-151 — `send_error(408)` maps to status **408** with code `malformed_request`, a pairing that CORE-ERR-001 and the §12 table forbid (`malformed_request` is `400`, and `408` is not in the table). The branch is also unreachable because `Handler.timeout` is `None`. Fix in: server/aware_server/httpd.py. Delete the branch, or map it to `400`.
- [minor] server/aware_server/httpd.py:89-94 — HTTP framing is accepted when it is ambiguous. A request with both `Transfer-Encoding: chunked` and `Content-Length` is served using `Content-Length` (probe: `200`), and two differing `Content-Length` headers are resolved to the first (probe: `200`). RFC 9112 §6.3 requires rejecting both (CORE-HTTP-001). The risk is low on a local server, but it is the same class of desync as the second blocker. Fix in: server/aware_server/httpd.py. Return `400 malformed_request` with `close` when `Transfer-Encoding` is present or `get_all("Content-Length")` has more than one distinct value.
- [minor] tests/protocol/test_send.py:135-137 — `test_CORE_SEQ_001_one_counter...` asserts only `status >= 400` for four rejections whose comment names `403, 400, 400, 409`. If, say, the conflict case regressed to some other 4xx, the test would still pass. Fix in: tests/protocol/test_send.py. Assert the exact `(status, code)` pairs.
- [minor] tests/protocol/test_runtime.py:90-116 — the concurrency tests cover distinct-id sends and identical duplicates. Two CORE-SRV-004 races have no test: concurrent sends of one `id` with different fields (expect exactly one `201` and the rest `409 id_conflict`), and polls interleaved with sends (a poll never shows a gap that a later poll fills below its `next_cursor`). My probe found no defect, so this is regression protection only. Fix in: tests/protocol/test_runtime.py.
- [nit] server/aware_server/api.py:9 — `api` imports the private helper `_s` from `state`, and responses are built two ways: `%`-formatted JSON (session, send, poll) and `json.dumps` (info, users). Move the string helper to `jsonvalue` and use one style. Fix in: server/aware_server/.
- [nit] server/aware_server/httpd.py:63-64 — `self.path.partition("?")` is computed twice. Use `path, _, query = self.path.partition("?")`. Fix in: server/aware_server/httpd.py.
- [nit] server/aware_server/httpd.py:18 — `\s` in `CONTENT_TYPE_RE` is Unicode-aware, so `Content-Type: application/json\xa0` (NBSP) is accepted (probe: `200`). Use `[ \t]*` (HTTP OWS). Fix in: server/aware_server/httpd.py.
- [nit] tests/protocol/test_send.py:117 — the comment cites "spec-issues.md S-3", but the payload-type question is S-1. Fix in: tests/protocol/test_send.py.
- [nit] tests/protocol/test_time.py:118 — the CORE-TIME-003 denylist does not catch the local-time forms `time.strftime(fmt)` with one argument, `time.ctime` and `time.asctime`. The production code is clean today (`grep` finds one time call, `time.strftime(..., time.gmtime(...))` at state.py:15). Fix in: tests/protocol/test_time.py.
- [nit] generator/scripts/check_schema_examples.py:86 — `pattern` is checked with Python `re.search`, where `$` also matches before a trailing `\n`. Anchored schema patterns therefore accept `"bob\n"`, unlike JSON Schema (ECMA) semantics. The server itself uses `fullmatch` and rejects such values, as the tests confirm. Fix in: generator/scripts/check_schema_examples.py (match with `\Z` semantics), outside the server boundary.
- [nit] tests/protocol/test_runtime.py:127 — S-7 says `OPTIONS` outside `/v1` is `404`, and the probe confirms it, but no test asserts it. Fix in: tests/protocol/test_runtime.py.

## Verified as conforming (no finding)

- **Concurrency and atomicity (CORE-SRV-004, CORE-SEQ-001):** registration, the duplicate check, seq assignment, storing, mailbox append and the E4 read all run under one `threading.Lock` (state.py:60-98). The clock is read only for new envelopes, inside the lock. Stress at 4/16/64 threads: 201 seqs contiguous from 1, polls strictly ascending, each duplicate id accepted once with identical `seq` and `accepted_at`. The one atomicity break is the first blocker (an exception after `_seq += 1`).
- **Epoch (CORE-EPOCH-001/002, CORE-SRV-010/015):** 16 hex characters from `secrets`, constant for the process. Missing or malformed → `400`, other epoch → `409`, at the CORE-SRV-030 step (3) position. Present in every E3/E4 success.
- **Cursor and poll (CORE-POLL-001..007, CORE-SRV-016):** canonical decimal patterns, `limit=0` rejected, clamping, `bisect` on `seq > after`, correct `has_more` and `next_cursor`, side-effect free, implicit mailboxes, always answered at once, `wait` ignored.
- **Strict UTC (CORE-HTTP-007, CORE-SRV-030/031/037):** `is_timestamp` checks the exact pattern plus the Gregorian calendar and leap years with no leap second. It accepts every valid case in `schema/cases/timestamp.json` and rejects every invalid one, plus extra cases. `accepted_at` comes from `time.time_ns()` formatted through `gmtime`, with milliseconds truncated. Correct under `TZ=Asia/Tokyo`, `America/Sao_Paulo` and `Pacific/Kiritimati`. **CORE-TIME-003:** no zone identifier, offset, abbreviation or local-time API anywhere in `server/` (my grep, plus the suite's denylist).
- **Error codes and order (CORE-ERR-001/002, CORE-SRV-011/030):** 415 → 413 (body unread) → malformed → epoch → name(from, to) → id → type → payload → unknown_sender → id_conflict, as specified. Every table code is produced with its status, and pre-routing failures still get the JSON body. The only departures are the minor about nesting order and the dead 408 mapping.
- **Dedupe (CORE-MSG-001, CORE-SRV-034/035):** canonical names compared, payload equality by JSON value (numbers compared as `Decimal` by value; bool, null and string kept distinct), `created_at` compared as an opaque string. Number spelling is returned verbatim.
- **No features beyond the spec:** no persistence, push, auth or test endpoint. The `ServerState(epoch, clock)` seams cannot be reached from the CLI or the environment (S-13). The duplicate-query-parameter `400` (S-5) and the nesting bound (S-10) are the only invented behaviors, and both are listed for TL.
- **Test quality overall:** every response read through `Client.call` is validated against the endpoint's schema, the error body and status pairing, `Content-Type` and CORS. The validator supports every keyword the schemas use. Appendix A is replayed exactly (fixed epoch and clock), including the lost-ack variant. Test names carry rule ids, and the assertions match the names except for the two majors and the minor at test_send.py:135.
- **Code simplicity:** small modules with clear layering (http → api → state). Standard library only. Readable.

## Notes

- Both blockers have small, local fixes. The second blocker and the framing minor share one fix: close the connection whenever the request body was not consumed exactly.
- A suggested convention for later suites: open protocol tests on one keep-alive connection at least once per error path. Fresh connections hide framing bugs.
